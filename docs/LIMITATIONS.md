# 数据与评测的限制说明（初稿）

> 作者：C（实验与评测）· 2026-11-14 12:48 初稿 · 正式成绩出来后补完第 5 节
> 用途：交给 D 放进报告、项目说明和 PPT。第 0 节可以直接做成一页 PPT；第 1–4 节放进项目说明。
> 原则：只写实际做过、测过的东西；没测的写"未评估"，不写成优点。

## 0. 一页版（PPT 用）

**我们的结论成立的范围**
- 两个公开的表格二分类任务：Bank Marketing（2008–2010 年葡萄牙银行电话营销）和 Adult（1994 年美国人口普查）。
- 一个 LLM（型号待定）、同一套受限的研究空间，以及相同的切分、种子和硬预算。
- 每个系统每个任务重复 3 次（以最终配置为准）。

**我们没有证明的**
- 不是统计显著性结论：所有"通过 / 胜出"都是事先固定的工程门槛。
- 不代表对未来数据的效果：切分是随机分层的，没有测试时间漂移。
- 不是通用 AutoML：只有 3 个 sklearn 模型族和 4 种特征动作，也没有和 FLAML、AutoGluon 这类强 AutoML 做对比。
- 不是持续学习：跨任务的经验库没有实现（如果 B 在冻结前完成，再改这一条）。
- 不是安全沙箱：训练在带超时的子进程里运行，holdout 是靠文件级别隔离的。

## 1. 数据与任务

| 限制 | 具体情况 | 影响 |
|---|---|---|
| 任务数量少 | 正式成绩只有 Bank 和 Adult 两个任务（乳腺癌数据只用于冒烟测试，不计成绩） | 只能说明在这两个任务上的表现，不能推广到"表格任务普遍有效" |
| 只支持二分类表格 | 多分类、回归、时间序列、文本、图像都没有实现；上传 CSV 时会直接拒绝 | 对话页能处理的任务类型有限 |
| 随机分层切分偏乐观 | Bank 数据按时间排列，`emp.var.rate`、`euribor3m` 等宏观经济列随时间变化；随机切分让训练集和测试集来自同一时期 | 分数代表"同一时期的新客户"，不代表下一轮营销活动；时间切分在 Schema 里有定义，但 Runner 没有实现 |
| 数据年代久远 | Adult 是 1994 年的数据，Bank 是 2008–2010 年的数据 | 收入水平和经济环境早已变化，只适合作为方法对比的基准 |
| 公开、知名的数据集 | 两个数据集在网上被大量讨论（例如"Bank 的 `duration` 会泄漏结果"） | LLM 可能记得这些知识；就算协议 Agent 正确排除了 `duration`，也不能完全说明是靠推理得出的，汇报时要提到这一点 |
| holdout 只有一份 | Bank 的 holdout 有 8,238 行（正例 11.3%），Adult 有 9,769 行（正例 23.9%），各只评一次 | 单个 holdout 分数本身有抽样误差，几个千分点的差异不足以区分系统；目前还没有计算置信区间（见第 6 节） |
| 受保护属性 | Adult 保留了 `race` 和 `sex`，和标准基准一致 | 没有做公平性评估；真实部署前需要审查 |
| 字段可用性由人确认 | 场景卡由人编写（Bank 按官方说明排除 `duration`）；协议 Agent 只起草，最终以人确认的为准 | 正式矩阵用的是人写的场景卡，对比结果不包含"理解业务约束"这部分的贡献；这部分要单独报告协议 Agent 的首次正确率 |

## 2. 评测方法

| 限制 | 具体情况 | 影响 |
|---|---|---|
| 裁决是工程门槛，不是显著性检验 | 候选通过的条件：同折配对差的均值 ≥ `min_effect`。其中 `min_effect` = max(0.002, 基线在 5 个标定切分上的标准差)，在第一次提案前就固定下来。之后还要在 3 个新的切分种子上复核：中位差 ≥ `min_effect`，且至少 2/3 为正 | CV 各折之间相关，不能把它当 p 值；可以说"事先固定的工程门槛"，不能说"显著" |
| 配对胜负也是同样的门槛 | 每个系统和随机搜索在同一次重复下比 holdout；差值超过两者 `min_effect` 中的较大值，才算胜或负 | "3 次里赢 2 次"是描述性的结果，不是显著性结论 |
| 重复次数少 | 正式矩阵每个系统、每个任务重复 3 次；只是 `search_seed` 不同，切分和训练种子都一样 | 只能报告均值 ± 标准差和逐次的原始结果；LLM 本身也不确定，3 次不足以估计它的方差 |
| 只用了一个 LLM | 所有 LLM 角色共用同一个模型 | 结论只适用于这个模型；换模型以后，成本和效果都可能不一样 |
| 相对基线的提升只能用开发集分数 | holdout 只评最终交付的方案一次，基线模型不在 holdout 上评测 | "比基线提升了多少"用的是开发集（5 折 CV）分数；系统之间的 holdout 比较看配对表 |
| 研究空间有限 | 3 个模型族（LR、RF、HGB）、类别权重、4 种特征动作（删列、log1p、缺失标记、哨兵值转缺失）；TF-IDF 已实现，但两个任务都没有文本列 | 天花板受空间限制；LLM 的优势只能体现在"在这个空间里选得更好、更省" |
| 对照组 | 零 Token 的对照是"同一空间的随机搜索"，实验数上限为 18（2 × 最大轮数 + 初始工具搜索），而不是相同的墙钟时间 | 它不是完整的 AutoML；如果按"相同时间"来比较，结果可能不同 |
| 停止点不同 | 各系统按照自己的停止规则结束（轮数用完、收益递减、没有新候选、预算用完），实验数并不相等 | 比较时要同时看分数、实验数、fit 数、Token 和时间，不能只看分数 |
| 耗时依赖机器 | 正式矩阵在一台 Apple Silicon Mac 上串行运行，每次 fit 限制为单线程，运行期间不跑其他任务 | 墙钟时间只能用于同一矩阵内部比较，换一台机器就不可比 |
| Token 与费用 | Token 取自提供方原始 HTTP 响应里的 usage；没有返回 usage 的请求按保守估计记为 unknown；只有知道单价时才计算费用 | 报告里同时给出已知 Token 和 unknown Token；单价未知时只报 Token，不报金额 |

## 3. 系统与工程

| 限制 | 具体情况 |
|---|---|
| 隔离级别 | 训练在带超时的子进程里运行；holdout 放在 `data/sealed/`，只有评测模块会读，研究代码只加载开发集文件。这是同一台机器上的文件级隔离，**不是操作系统层面的沙箱**，不能称为"安全沙箱" |
| LLM 的权限 | LLM 只能输出受控的实验规格（Schema 严格校验），不能执行任意代码；自定义特征函数没有实现 |
| 调度由规则触发 | "停滞时插入随机搜索、请 Critic、重规划"由事先固定的规则触发，不是 LLM 自己决定的；方向变化分别统计（agent / rule / error） |
| 持续学习 | 跨任务经验库没有实现（P1）；不能声称"越用越好" |
| 对话页的 run | 演示时在网页上跑出的 run 不计入正式成绩；正式成绩只来自冻结版本跑出的 `results/final-*` |
| 可复现性 | 数据哈希、切分清单、代码版本（git 提交和是否有未提交改动）、依赖锁、种子都有记录；训练可以按规格复现。但 LLM 生成的提案不一定能复现，所以"重新研究"和"历史回放"要分开描述 |

## 4. 推荐的表述

| ✅ 可以这样说 | ❌ 不要这样说 |
|---|---|
| "在两个公开二分类任务、3 次重复中，BudgetLab 相比同一空间的随机搜索 ……（以正式结果为准）" | "显著优于"、"全面超越 AutoML" |
| "每个结论都能回溯到配置、切分、日志和程序计算的指标" | "保证正确"、"零错误" |
| "按事先固定的工程门槛判定，并在 3 个新切分上复核" | "统计检验证明" |
| "协议 Agent 在 Bank 上首次就排除了 `duration`（附正确率和成本）" | "Agent 自主发现了数据泄漏"（没测过，或者是人写的场景卡时） |
| "Token 和费用按提供方返回的 usage 记账，未知部分单独列出" | "成本降低 X%"（除非配对比较里确实测到了） |
| "训练运行在带超时的子进程里，holdout 做了文件隔离" | "安全沙箱" |
